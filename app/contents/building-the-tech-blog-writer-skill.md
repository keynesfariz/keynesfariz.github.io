> TL;DR: Jumping back and forth between Claude, terminal, and my code editor was killing my writing mood. So I just built an AI skill right into my IDE to automate the whole thing 😃.

I've been trying to write more lately. The goal is actually simple: I just want my thoughts to be structured, grammatically correct, and actually published. In the beginning, I only used AI (like Claude chat) to help me with outlining the post and fixing my broken grammar. But the friction to just get a single post out the door was surprisingly too much.

## The Old Way Was Tedious

Before this, writing a blog post literally felt like juggling. I already had a simple script to generate the markdown template (`lib/writing-generator.ts`), but well, that was just step one.

The workflow looked something like this:

1. Open terminal, run the script to create the file.
2. Open Claude in a browser to help me outline and draft the content.
3. Copy-paste back and forth between Claude and my editor.
4. Realize I need an image. Open terminal again, run `cwebp` manually to compress it.
5. Manually type out the markdown image links.
6. Commit the changes, push the branch, and open GitHub to create a Pull Request.

That's a whole lot of app switching just to write some text. The generator script and the AI chat were completely separated from each other. It was tedious, and honestly, it made me lazy to even start writing.

![Old workflow illustration generated by ChatGPT](/assets/building-the-tech-blog-writer-skill-old-workflow.webp)

## The "Wait, I Can Automate This" Moment

Since I'm already playing around in the AI space, it hit me: why am I acting as the manual human bridge between all these tools? I should just leverage Antigravity's architecture to handle the whole orchestration for me.

So, I built a custom **Skill** specifically for this repository.

![Screenshot of the Antigravity IDE showing the skill in action](/assets/building-the-tech-blog-writer-skill-ide-action.webp)

## How It Works Under The Hood

By just placing a `SKILL.md` file inside the `.agents/` folder of my project, I basically taught my local AI assistant how to be my personal editor.

Here is a summarized version of the prompt I used to bootstrap the skill:

> "Guide me to create a workflow to help me write blog posts. The flow: you run my generator script to create the markdown file, ask me questions to outline the post, write the draft, handle any image conversions using `cwebp` on my machine, and finally push a PR for me to review."

Now, when I want to write a post, I just type "Help me write a new tech blog post." The agent immediately:

- Runs the local `bun` script to generate the file.
- Drafts the initial content right in my editor based on our chat.
- Asks for my images, runs the `cwebp` shell commands behind the scenes, and injects the links.
- Uses Git commands to create a branch, commit, push, and open a PR.

It completely cuts out the annoying context switching. I can stay in one window, focus on my actual ideas, and just let the AI handle the mechanical drudgery of file creation, image compression, and git stuffs.

## Iterating on the Fly

The beauty of having this skill running locally is that it's literally just a Markdown file (`SKILL.md`). If I want the agent to do something differently, I just tell it to update its own instruction file.

For example, right after building the first version, I realized I was still manually writing the post descriptions in the markdown frontmatter, and the GitHub Pull Requests were opened with generic titles. So I just threw this at the agent: _"Update the skill to also generate a post description, and use the title and description when creating the PR."_

Now, the agent automatically generates a 1-2 sentence summary for the frontmatter and passes `--title` and `--body` flags to the GitHub CLI. Continuous improvement with literally zero context switching.
